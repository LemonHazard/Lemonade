- Reloading while the Visual Studio debugger is attached will also need Casey’s unique-PDB-name trick, which isn’t in yet.
- Meshes are copied to the GPU the first time they're drawn and kept until exit, recognized by their data's address: vertices or indices changed in place aren't picked up, nothing is freed, and past 4096 meshes or 128 MiB of them new ones aren't drawn. A frame uploads at most 16 MiB of new meshes: the rest show up a frame or more later, and a single mesh bigger than that is never drawn. Each of these limits logs a warning once.
- Only Linux draws anything: the Vulkan renderer is Linux-only, so Windows and macOS build with the null renderer. macOS has no window code at all yet.
- The Windows window doesn't read the keyboard or mouse, so key bindings do nothing there.
- Gamepads aren't read yet, although input.h already lists their keys.
- Assets are only loaded at startup: editing a .glb or key_bindings.kvl needs a restart, unlike code changes.
- Textures are copied to the GPU the first time they're drawn and kept until exit, recognized by their pixels' address: pixels changed in place aren't picked up, nothing is freed, and past 256 textures meshes are drawn white. The first draw of a texture also stalls the frame until its upload is done; it could go through the frames' staging buffers and upload command buffers like meshes do instead.
