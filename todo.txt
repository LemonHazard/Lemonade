- Reloading while the Visual Studio debugger is attached will also need Casey’s unique-PDB-name trick, which isn’t in yet.
- Mesh data gets copied to the GPU every frame. That’s fine for a few simple models; it will need changing once scenes get large.
- Only Linux draws anything: the Vulkan renderer is Linux-only, so Windows and macOS build with the null renderer. macOS has no window code at all yet.
- The Windows window doesn't read the keyboard or mouse, so key bindings do nothing there.
- Gamepads aren't read yet, although input.h already lists their keys.
- frame.dt isn't capped: after a debugger pause, a slow reload or a dragged window the first frame can be seconds long and things jump.
- Assets are only loaded at startup: editing a .glb or key_bindings.kvl needs a restart, unlike code changes.
- When the render command buffer is full, push_render_command() drops the command without logging anything.
